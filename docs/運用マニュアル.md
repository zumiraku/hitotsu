# ヒトツ 運用マニュアル

日々使う人向けの説明と、管理者向けの手順をまとめたもの。導入手順は [デプロイ手順](デプロイ手順.md)、開発者向けは [README](../README.md)。

## 1. 画面の使い方

### ホーム
- 上の「本日の状況」で、期限超過・今日期限・動きの止まっている案件・納期が近い案件が一文でわかる
- 右の「集計」の件数を押すとその一覧に飛ぶ。「期限が近いタスク」はチェックを入れるとその場で完了になる
- 「要確認の案件」の確認事項が赤いものは超過系、橙は放置・保留。先に赤から片付ける
- 担当者別の未完了タスクの氏名を押すと、その人のタスク一覧

### 顧客・取引先
- 会社名・フリガナ・先方担当・業種・タグで検索。種別と社内担当で絞り込み
- 詳細の基本情報の下にある「社内メモ」は担当が変わっても引き継がれる注意点を書く場所（請求の締め日、連絡の取りやすい手段など）
- 案件が残っている顧客は削除できない。削除しても変更履歴には残る

### 案件
- 「一覧」と「ボード」を切り替えられる。ボードはカードをドラッグするとステータスが変わり、すぐ保存される
- 詳細のステータスはプルダウンでその場で変更。要確認の理由が上に出る
- タスク・対応履歴・社内メモ・ファイルはすべて案件詳細から追加できる
- 金額は「120万」「1.5億」「1,200,000」のどの書き方でも登録できる

### タスク
- 期限超過／今日／今週／来週以降／期限なし／完了で並ぶ。「自分の担当」で自分の分だけ
- 行のチェックで完了。右端の「編集」「削除」で修正・削除

### 対応履歴
- 案件詳細（または顧客詳細）の下のフォームで「種別・日時・内容」を記録する。誰と・何を話して・次に何をするかを書くと引き継ぎ時に効く
- 電話／メール／訪問／来社／メモの5種類

### 社内メモ・引き継ぎ
- 「引き継ぎ」「ルール」「メモ」の3分類。ピン留めするとホームに出る
- 担当交代のときは案件詳細の「引き継ぎメモ作成」を押すと、対応履歴・未完了タスク・資料から下書きができる。内容を確認して保存する

### ファイル
- 案件か顧客に紐づけて追加する。同じ場所に同じ名前で追加すると第2版、第3版…として保存され、前の版も「過去の版」から取り出せる
- 1ファイルの上限は既定 50MB。exe などの実行形式は受け付けない

### 検索
- 画面上部の検索欄に単語を入れると、顧客・案件・タスク・メモ・ファイル・対応履歴を横断して候補が出る。「検索」を押すと結果画面
- 「田中さんの今週期限のタスク」「サクラ物産の進行中案件」「期限切れ」のような文でも探せる。解釈した条件が「検索条件：」として出るので、違っていたら言い方を変える
- 空白で区切ると AND 検索

### データ入出力
- CSV エクスポートは Excel でそのまま開ける（UTF-8 BOM 付き）
- インポートは「顧客・取引先 → 案件 → タスク」の順に。Excel の表をコピーして貼り付けてもよい。エラーは行番号と理由が出る

## 2. ロールと権限

| | 管理者 | マネージャー | 一般 | 閲覧のみ |
| --- | :-: | :-: | :-: | :-: |
| 閲覧 | ● | ● | ● | ● |
| 対応履歴・タスク・メモの追加 | ● | ● | ● | — |
| 顧客・案件の作成・編集 | ● | ● | ● | — |
| ファイルの追加・削除 | ● | ● | ● | — |
| 金額の閲覧 | ● | ● | ● | — |
| CSV エクスポート | ● | ● | ● | — |
| CSV インポート | ● | ● | — | — |
| 案件・顧客の削除 | ● | ● | — | — |
| 変更履歴の閲覧 | ● | ● | — | — |
| ユーザー・権限の管理 | ● | — | — | — |

権限は画面の表示だけでなく保存処理の側でも確認しているので、URL を直接叩いても抜けられない。

## 3. 管理者の手順

### ユーザーを追加する
1. 「ユーザー・権限」→「ユーザー登録」
2. 氏名・メール・所属・ロールを入れて「登録」
3. 表示された仮パスワードを本人に直接伝える（画面を閉じると再表示できない。必要なら「パスワード再発行」）
4. 本人が初回ログインするとパスワード変更を求められる

### 退職・異動のとき
- 「無効化」でログインできなくなる。担当していた顧客・案件・履歴はそのまま残る
- 担当の付け替えは各案件・顧客の編集画面で。まとめて変えたい場合は CSV エクスポート → 編集 → は使わず、DB 側で一括更新する（開発者に依頼）

### パスワードを忘れた
- 管理者が「パスワード再発行」→ 仮パスワードを伝える → 本人が初回ログインで変更

### 変更履歴を見る
- 「変更履歴」で誰が・いつ・何を変えたかを対象・操作・ユーザー・期間で絞り込める
- 各案件・顧客の詳細にもその対象の履歴が出る

## 4. バックアップと復元

### 取る
- サーバーで `./scripts/backup.sh` を実行すると `backups/` に DB（`db_日時.dump`）とファイル（`storage_日時.tar.gz`）ができる
- cron で毎日取る設定は [デプロイ手順](デプロイ手順.md#6-バックアップ) 参照。30 日より古いものは自動削除
- `backups/` は必ず別の場所（別サーバーやオブジェクトストレージ）にも写す

### 戻す
1. 今の状態も念のためバックアップを取る
2. `./scripts/restore.sh backups/db_XXXX.dump backups/storage_XXXX.tar.gz`
3. アプリが再起動したら、ログインして直近のデータがあるか確認

Windows で動かしている場合は `scripts\backup.ps1`（DB のパスワードは環境変数 `DB_PASSWORD`）。

## 5. 困ったとき

| 症状 | 見るところ・対処 |
| --- | --- |
| 画面が開かない | `docker compose ps` で app / db が起動しているか。`docker compose logs --tail=100 app` |
| ログインできない | 無効化されていないか（ユーザー・権限）。5 回失敗すると 15 分ロック。HTTP で開いていないか（本番は HTTPS 必須） |
| `/api/health` が `db: down` | DB コンテナの状態と `DB_PASSWORD` が変わっていないか |
| ファイルが開けない | `storage` ボリュームが残っているか。S3 の場合は認証情報 |
| 検索が遅い | データが数十万件を超えたら DB のメモリ設定を見直す。`pg_trgm` のインデックスが効いているか |
| 更新後に画面が崩れる | ブラウザのキャッシュを消す（強制再読み込み） |

問い合わせのときは、発生日時・操作していた画面・ログインユーザー・表示されたメッセージを添える。

## 6. 環境変数一覧

| 変数 | 既定 | 内容 |
| --- | --- | --- |
| `DATABASE_URL` | — | PostgreSQL の接続文字列 |
| `STORAGE_DRIVER` | `local` | `local` または `s3` |
| `STORAGE_DIR` | `./storage` | local のときの保存先 |
| `MAX_UPLOAD_MB` | `50` | 1 ファイルの上限 |
| `S3_BUCKET` / `S3_REGION` / `S3_ENDPOINT` / `S3_ACCESS_KEY_ID` / `S3_SECRET_ACCESS_KEY` | — | S3 互換ストレージ |
| `ANTHROPIC_API_KEY` | — | 設定すると AI アシスト（文章整形・検索の解釈）が有効 |
| `AI_MODEL` | `claude-opus-5` | AI アシストのモデル |
| `TZ` | `Asia/Tokyo` | 日付判定に使う。変更しない |
