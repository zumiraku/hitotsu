# ヒトツ 開発計画

社内に散らばった Excel・スプレッドシート・各種ツールの情報を一元管理する業務管理システム。
MVP を早く動かして、運用しながら段階的に育てる前提で、次の 10 ステージに分けて進める。

## 技術構成

| 領域 | 採用 | 理由 |
| --- | --- | --- |
| フレームワーク | Next.js 16（App Router / TypeScript） | 画面と API を 1 つのコードベースで持てる。Server Components で DB 直読みができる |
| DB | PostgreSQL 17 | 無料・容量制限なし（ディスク次第）。行単位のアクセス制御、全文検索、JSON など業務システムに必要な機能が揃う |
| ORM | Prisma 7 | スキーマ＝設計書として読める。マイグレーション履歴が残る |
| スタイル | Tailwind CSS 4 | 共通トークンを 1 か所で管理 |
| 認証 | Cookie セッション + bcrypt（ステージ7） | 外部サービスに依存しない |
| ファイル保存 | ローカルディスク → 必要になったら S3 互換ストレージへ差し替え | 最初から抽象化しておく |

DB はローカル PostgreSQL で開始し、本番は Supabase / Neon / 自前サーバーのどれにでも同じスキーマで移せる。

## ステージ

### ステージ 1　基盤構築 ✅
- リポジトリ作成、Next.js + TypeScript + Tailwind の雛形
- PostgreSQL 17 のローカルセットアップ、Prisma 導入
- 全テーブルのスキーマ設計と初回マイグレーション（ユーザー、顧客・取引先、案件、メンバー、タスク、対応履歴、社内メモ、ファイル、変更履歴）
- 動作確認用のシードデータ
- 共通レイアウト（サイドバー・ヘッダー）、ダッシュボードの土台、ヘルスチェック API

### ステージ 2　顧客・取引先管理 ✅
- 一覧（検索・種別/担当での絞り込み・並び替え・ページング）
- 詳細（基本情報・先方担当・関連案件・対応履歴・ファイル）
- 登録・編集・論理削除、コード自動採番
- 入力検証（zod）と Server Actions

### ステージ 3　案件・進捗管理 ✅
- 一覧とかんばんボード（ドラッグでステータス変更）
- 詳細（概要・メンバー・タスク・対応履歴・ファイル・社内メモ）
- 登録・編集・ステータス変更、要確認アラート（納期超過・放置・保留）

### ステージ 4　タスク・期限・ダッシュボード ✅
- 期限グループ表示（超過／今日／今週／来週以降／期限なし）、完了操作
- ダッシュボードの本実装（KPI、要確認案件、14 日カレンダー、ステータス分布）

### ステージ 5　対応履歴・社内メモ・引き継ぎ ✅
- 電話／メール／訪問／来社／メモの記録、タイムライン表示
- 社内メモ（引き継ぎ・ルール・メモ）、ピン留め、案件・顧客への紐づけ

### ステージ 6　ファイル管理 ✅
- アップロード（案件・顧客に紐づけ）、同名ファイルの版管理
- ストレージ抽象化（ローカル → S3 互換）

### ステージ 7　ユーザー・権限・変更履歴 ✅
- ログイン、招待、パスワード変更
- ロール（管理者／マネージャー／一般／閲覧のみ）と権限マトリクス、画面と Server Action の両方で強制
- 変更履歴（作成・更新・削除・ステータス変更・権限変更・入出力）の自動記録と一覧

### ステージ 8　検索・絞り込み・CSV 入出力 ✅
- 横断検索（顧客・案件・タスク・ファイル・メモ・対応履歴）。日本語の部分一致を pg_trgm のインデックスで速くする
- CSV エクスポート／インポート（見出しの自動対応づけ、プレビュー、Excel からの貼り付け）

### ステージ 9　AI アシスト ✅
- 引き継ぎメモの自動下書き（対応履歴・タスク・メモから生成）
- 自然言語での検索（「田中さんの今週期限のタスク」）
- 効果が見えた箇所から段階的に有効化。AI 導入自体を目的にしない
- API キーなしでもルールベースで動き、キーを設定すると文章整形と検索の解釈に AI を使う

### ステージ 10　テスト・本番導入 ✅
- 自動テスト（主要な Server Action と権限）、本番ビルド
- Docker Compose、バックアップ手順、運用マニュアル、本番デプロイ

## 進め方
- 1 ステージ＝動く状態でコミット。ステージ内でも機能ごとに小さくコミットする
- 各ステージの終わりに `npm run build` と `npm run lint` が通ることを確認する
- スキーマ変更は必ずマイグレーションで残す（`prisma/migrations`）
