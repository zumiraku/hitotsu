# デプロイ手順（Docker Compose）

Linux の VPS 1 台で動かす想定。DB・アプリ・ファイルをすべて同じサーバーに置く。
利用人数が数十人・データが数万件までなら 2 vCPU / 4 GB メモリで十分。

## 前提

- Docker と Docker Compose v2（`docker compose version` が動くこと）
- ドメインとその DNS が VPS を向いていること（HTTPS 用）
- ポート 80 / 443 が開いていること

## 1. 取得と設定

```bash
git clone <このリポジトリ> /opt/hitotsu
cd /opt/hitotsu
cp .env.docker.example .env
```

`.env` を編集する。最低限 `DB_PASSWORD` を長いランダム文字列にする（`openssl rand -base64 32` など）。

| 変数 | 内容 |
| --- | --- |
| `DB_PASSWORD` | DB のパスワード。必須 |
| `APP_PORT` | ホスト側で公開するポート（既定 3000。リバースプロキシ経由なら変更不要） |
| `STORAGE_DRIVER` | `local`（既定）または `s3` |
| `MAX_UPLOAD_MB` | 1 ファイルの上限 |
| `S3_*` | S3 互換ストレージを使う場合 |
| `ANTHROPIC_API_KEY` / `AI_MODEL` | AI アシストを使う場合（任意） |

## 2. 起動

```bash
docker compose up -d --build
docker compose logs -f app   # 「Ready」が出れば起動
curl http://localhost:3000/api/health   # {"ok":true,"db":"up",...}
```

`migrate` サービスが先にマイグレーションを流し、終わってから `app` が起動する。
2 回目以降の `docker compose up -d --build` でも同じ流れで、未適用のマイグレーションだけが適用される。

## 3. 最初のユーザー

本番では seed を入れない。代わりに管理者を 1 人作る。

```bash
docker compose run --rm migrate npx tsx scripts/create-admin.ts admin@example.co.jp "管理者 太郎" "最初の仮パスワード"
```

そのアカウントでログインするとパスワード変更を求められる。以後のユーザーは画面の「ユーザー・権限」から登録する。

## 4. HTTPS（Caddy の例）

アプリの前に Caddy を置くと証明書の取得・更新まで自動になる。`docker-compose.yml` と同じディレクトリに `Caddyfile` を置き、compose にサービスを 1 つ足す。

```
# Caddyfile
hitotsu.example.co.jp {
    reverse_proxy app:3000
    request_body {
        max_size 60MB
    }
}
```

```yaml
  # docker-compose.yml に追加
  caddy:
    image: caddy:2-alpine
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy-data:/data
    depends_on:
      - app
```

`volumes:` に `caddy-data:` を追加し、`app` の `ports` は外し（Caddy 経由のみにする）。
Cookie は本番（`NODE_ENV=production`）では `Secure` 属性付きになるので、HTTP のままではログインできない。必ず HTTPS で公開する。

## 5. 更新

```bash
cd /opt/hitotsu
./scripts/backup.sh                 # 念のため
git pull
docker compose up -d --build        # マイグレーション → 再起動
docker compose logs --tail=50 app
```

## 6. バックアップ

`scripts/backup.sh` が DB（pg_dump）とアップロードファイルを `backups/` にまとめる。30 日より古いものは自動で消える。

```bash
# 毎日 3 時に取る
crontab -e
0 3 * * * cd /opt/hitotsu && ./scripts/backup.sh >> backups/backup.log 2>&1
```

`backups/` は別のサーバーやオブジェクトストレージへも同期しておく（同じサーバーだけに置かない）。
復元は `./scripts/restore.sh backups/db_XXXX.dump backups/storage_XXXX.tar.gz`。詳しくは [運用マニュアル](運用マニュアル.md)。

## 7. S3 互換ストレージに切り替える

ファイルが増えてきたら `.env` の `STORAGE_DRIVER=s3` と `S3_*` を設定して再起動する。
既存ファイルは `storage` ボリュームから S3 へコピーし、DB の `files.storagePath` はそのまま使える（キーは同じ）。

## 動作要件

- Node.js 22（コンテナに同梱）
- PostgreSQL 17（`pg_trgm` 拡張。公式イメージに含まれる）
- タイムゾーンは `Asia/Tokyo` に固定してある（日付の判定に使う）
